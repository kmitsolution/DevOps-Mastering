## **2. Configure VirtualBox NAT Network**

Your original lab uses a VirtualBox NAT Network named `inputnetwork`.

Create this network once from the Windows command prompt:

```
VBoxManage natnetwork add `
  --netname inputnetwork `
  --network "192.168.0.0/24" `
  --enable `
  --dhcp off
```

If the network already exists, you don't need to create it again.

**Important:** Vagrant's normal `private_network` creates a host-only network, not your existing NAT Network. The Vagrantfile below attaches the second adapter directly to `inputnetwork` to preserve your original lab topology.

## **3. Create the Vagrantfile**

Save the following as `Vagrantfile` in the project root.

```

Vagrant.configure("2") do |config|

  config.vm.box = "ubuntu/noble64"

  # Common VirtualBox configuration
  config.vm.provider "virtualbox" do |vb|
    vb.gui = false
  end

  # Attach Adapter 2 to existing VirtualBox NAT Network
  def configure_network(vm, ip)
    vm.vm.provider "virtualbox" do |vb|
      vb.customize [
        "modifyvm", :id,
        "--nic2", "natnetwork",
        "--nat-network2", "inputnetwork"
      ]
    end

    vm.vm.provision "shell",
      inline: <<-SHELL
        cat > /etc/netplan/60-kubernetes-static.yaml <<EOF
network:
  version: 2
  ethernets:
    enp0s8:
      dhcp4: false
      addresses:
        - #{ip}/24
EOF

        chmod 600 /etc/netplan/60-kubernetes-static.yaml
        netplan apply
      SHELL
  end

  # -------------------------
  # MASTER NODE
  # -------------------------

  config.vm.define "kmaster" do |master|

    master.vm.hostname = "kmaster"

    master.vm.provider "virtualbox" do |vb|
      vb.name = "kmaster"
      vb.memory = 4096
      vb.cpus = 2
    end

    configure_network(master, "192.168.0.5")

    master.vm.provision "shell",
      path: "scripts/common.sh"

    master.vm.provision "shell",
      path: "scripts/master.sh"

  end

  # -------------------------
  # WORKER 1
  # -------------------------

  config.vm.define "worker1" do |worker|

    worker.vm.hostname = "worker1"

    worker.vm.provider "virtualbox" do |vb|
      vb.name = "worker1"
      vb.memory = 2048
      vb.cpus = 2
    end

    configure_network(worker, "192.168.0.6")

    worker.vm.provision "shell",
      path: "scripts/common.sh"

    worker.vm.provision "shell",
      path: "scripts/worker.sh"

  end

  # -------------------------
  # WORKER 2
  # -------------------------

  config.vm.define "worker2" do |worker|

    worker.vm.hostname = "worker2"

    worker.vm.provider "virtualbox" do |vb|
      vb.name = "worker2"
      vb.memory = 2048
      vb.cpus = 2
    end

    configure_network(worker, "192.168.0.7")

    worker.vm.provision "shell",
      path: "scripts/common.sh"

    worker.vm.provision "shell",
      path: "scripts/worker.sh"

  end

end

```

## **4. Common installation script – common.sh**

This script executes on all three machines.

It performs:

1. System update.
2. Installation of containerd.
3. Configuration of containerd.
4. Installation of kubelet, kubeadm and kubectl.
5. Swap disablement.
6. Kernel module and network configuration.

Create `scripts/common.sh`.

```

#!/bin/bash
set -e

echo "===================================="
echo "Installing Kubernetes prerequisites"
echo "===================================="

export DEBIAN_FRONTEND=noninteractive

# Update packages
apt-get update
apt-get install -y curl gpg ca-certificates apt-transport-https

# Add Docker repository key
install -m 0755 -d /etc/apt/keyrings

curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc

chmod a+r /etc/apt/keyrings/docker.asc

# Add Docker repository
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo ${UBUNTU_CODENAME:-$VERSION_CODENAME}) stable" \
  > /etc/apt/sources.list.d/docker.list

apt-get update

# Install containerd
apt-get install -y containerd.io

# Configure containerd
mkdir -p /etc/containerd

containerd config default > /etc/containerd/config.toml

# Enable systemd cgroup driver
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' \
  /etc/containerd/config.toml

systemctl restart containerd
systemctl enable containerd

# Add Kubernetes repository
curl -fsSL \
  https://pkgs.k8s.io/core:/stable:/v1.35/deb/Release.key \
  -o /etc/apt/keyrings/kubernetes-apt-keyring.asc

cat > /etc/apt/sources.list.d/kubernetes.list <<EOF
deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.asc] https://pkgs.k8s.io/core:/stable:/v1.35/deb/ /
EOF

apt-get update

# Install Kubernetes components
apt-get install -y kubelet kubeadm kubectl

# Hold Kubernetes packages
apt-mark hold kubelet kubeadm kubectl

systemctl enable kubelet

# Disable swap now and after reboot
swapoff -a
sed -i '/\sswap\s/s/^/#/' /etc/fstab

# Load required kernel modules
cat > /etc/modules-load.d/k8s.conf <<EOF
overlay
br_netfilter
EOF

modprobe overlay
modprobe br_netfilter

# Configure networking
cat > /etc/sysctl.d/k8s.conf <<EOF
net.ipv4.ip_forward = 1
net.bridge.bridge-nf-call-iptables = 1
net.bridge.bridge-nf-call-ip6tables = 1
EOF

sysctl --system

echo "Common Kubernetes installation completed"

```

## **5. Master installation script – master.sh**

This script executes only on `kmaster`.

It will:

1. Initialize the Kubernetes Control Plane.
2. Configure kubectl.
3. Install Flannel.
4. Generate the worker join command automatically.
5. Save the join command in the shared Vagrant folder.

Create `scripts/master.sh`.

```

#!/bin/bash
set -e

echo "===================================="
echo "Initializing Kubernetes Master"
echo "===================================="

# Initialize Kubernetes Control Plane
if [ ! -f /etc/kubernetes/admin.conf ]; then

  kubeadm init \
    --apiserver-advertise-address=192.168.0.5 \
    --pod-network-cidr=10.244.0.0/16 \
    --cri-socket=unix:///run/containerd/containerd.sock \
    --node-name=kmaster

fi

# Configure kubectl for Vagrant user
mkdir -p /home/vagrant/.kube

cp -f /etc/kubernetes/admin.conf \
  /home/vagrant/.kube/config

chown -R vagrant:vagrant /home/vagrant/.kube

export KUBECONFIG=/etc/kubernetes/admin.conf

# Wait for API server
until kubectl get nodes >/dev/null 2>&1; do
  echo "Waiting for Kubernetes API server..."
  sleep 5
done

# Install Flannel
kubectl apply -f \
  https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml

# Wait for Flannel DaemonSet
kubectl -n kube-flannel rollout status \
  daemonset/kube-flannel-ds --timeout=300s

# Generate worker join command
echo "Generating Kubernetes worker join command..."

JOIN_COMMAND=$(kubeadm token create --print-join-command)

cat > /vagrant/kubeadm-join.sh <<EOF
#!/bin/bash
set -e
${JOIN_COMMAND} --cri-socket=unix:///run/containerd/containerd.sock
EOF

chmod 700 /vagrant/kubeadm-join.sh

echo "===================================="
echo "Master installation completed"
echo "===================================="

kubectl get nodes

```

## **6. Worker installation script – worker.sh**

This script executes on both `worker1` and `worker2`.

The important part is that you do not need to manually copy the token from the master.

The script waits until the master generates the join command in the shared folder.

Create `scripts/worker.sh`.

```

#!/bin/bash
set -e

echo "===================================="
echo "Joining Kubernetes Worker Node"
echo "===================================="

# Skip if already joined
if [ -f /etc/kubernetes/kubelet.conf ]; then
  echo "Node is already part of a Kubernetes cluster."
  exit 0
fi

# Wait for master to generate join command
echo "Waiting for Kubernetes master..."

for i in $(seq 1 180); do

  if [ -f /vagrant/kubeadm-join.sh ]; then
    break
  fi

  sleep 5

done

if [ ! -f /vagrant/kubeadm-join.sh ]; then
  echo "ERROR: Master join command not found."
  exit 1
fi

# Join Kubernetes cluster
bash /vagrant/kubeadm-join.sh

echo "===================================="
echo "Worker joined successfully"
echo "===================================="

```

## **7. Important network configuration adjustment**

There is one important detail in your original VirtualBox setup.

Your machines have two network adapters:

- Adapter 1: Vagrant's NAT adapter for internet access.
- Adapter 2: `inputnetwork` for communication between Kubernetes nodes.

The kubelet must use the second adapter's IP address, otherwise it may register using the NAT adapter's IP.

Inside the `configure_network` method in the Vagrantfile, add the following after the Netplan configuration:

```
    vm.vm.provision "shell",
      inline: <<-SHELL
        echo 'KUBELET_EXTRA_ARGS=--node-ip=#{ip}' > /etc/default/kubelet
        systemctl restart kubelet || true
      SHELL
```

Also, because Flannel must use the node-to-node interface, update its DaemonSet after applying the Flannel manifest in `master.sh`:

```
kubectl -n kube-flannel patch daemonset kube-flannel-ds \
  --type=json \
  -p='[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--iface=enp0s8"}]'
```

This assumes the second adapter is named `enp0s8`, as in your original lab. Verify the interface name using:

```
ip addr
```

The patch should be applied before checking the Flannel rollout status.

## **8. Start the Kubernetes cluster**

Open PowerShell in the `kubernetes-vagrant-lab` directory.

**Step 1 – Validate Vagrant configuration**

```
vagrant validate
```

**Step 2 – Start all three VMs**

```
vagrant up
```

Vagrant will:

1. Create `kmaster`.
2. Install containerd and Kubernetes packages.
3. Initialize the Kubernetes Control Plane.
4. Install Flannel.
5. Generate the worker join command.
6. Create `worker1` and join it to the cluster.
7. Create `worker2` and join it to the cluster.

**Step 3 – Check VM status**

```
vagrant status
```

**Step 4 – Connect to master**

```
vagrant ssh kmaster
```

**Step 5 – Verify Kubernetes cluster**

```
kubectl get nodes -o wide
```

Expected result:

```
NAME      STATUS   ROLES           VERSION
kmaster   Ready    control-plane   v1.35.x
worker1   Ready    <none>          v1.35.x
worker2   Ready    <none>          v1.35.x
```

The exact patch version depends on the packages available in the Kubernetes v1.35 repository.

## **11. One important difference from your manual installation**

Your manual installation requires you to copy the `kubeadm join` command from the master and paste it into both workers.

In this Vagrant implementation:

- Master generates the join token.
- Master writes the join command into `/vagrant/kubeadm-join.sh`.
- Vagrant shares this folder with all three machines.
- Workers automatically read the command and join the cluster.

No hardcoded token is required.

**Note:** This is a proposed Vagrant project configuration, not a tested installation. Validate it on your VirtualBox host before using it in a student lab. The NAT Network must exist, and the `enp0s8` interface assumption must be verified.
